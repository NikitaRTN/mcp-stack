# MCP Hub 3

Лёгкая self-hosted панель и рабочее пространство разработчика для нескольких MCP-серверов: один публичный порт, автоматический HTTPS через Caddy, создание и редактирование MCP, отдельная авторизация каждого маршрута, Tools Explorer и журнал каждого вызова инструмента в реальном времени.

## Главные свойства

- **Репозиторий меньше 250 КБ.** В нём нет Caddy, Node.js, `node_modules` или собранного frontend-бандла.
- **Установка из браузера.** Caddy загружается из официального GitHub Release, проверяется по SHA-256 и кладётся в `bin/`. Node.js на Windows ставится через `winget`; npm-пакеты прогреваются через `npx`.
- **Всё выключено по умолчанию.** Выключенный MCP не запускается, не публикуется в Caddyfile, не проверяется и не создаёт предупреждений.
- **MCP Studio.** Создание и редактирование локальных/удалённых MCP, управление портами, маршрутом и авторизацией без ручной правки конфига.
- **Windows UI Automation MCP.** Отдельный встроенный сервис для скриншотов, поиска доступных элементов, семантических кликов, ввода и ожидания окон без хрупких экранных координат.
- **Tools Explorer.** Подключение к одному выбранному MCP или произвольному URL, `tools/list`, input schema, JSON-аргументы и `tools/call` прямо в браузере.
- **Отдельная вкладка для каждого MCP.** Журнал показывает инструмент, JSON-RPC метод, время, длительность, результат, аргументы и текст ошибки.
- **OAuth на уровне сервиса.** Публичный маршрут: токен Hub, OAuth introspection или без auth; удалённый upstream: none, Bearer или OAuth Client Credentials.
- **Windows Firewall по разрешению.** Публичный HTTPS-порт добавляется только после подтверждения и системного UAC.
- **Без опроса сервера.** Панель получает события через SSE с автоматическим reconnect и `Last-Event-ID`. Caddy обслуживает клиентские соединения по HTTP/2; MCP-трафик не буферизуется.
- **Прозрачный инспектор.** Streamable HTTP и SSE проходят через локальный proxy, который понимает JSON-RPC и записывает телеметрию, не меняя MCP-сервер.
- **Без обязательных Python-зависимостей.** Backend работает на стандартной библиотеке Python 3.8+; данные хранятся в SQLite/WAL.

## Быстрый старт (Windows)

### Для обычного пользователя

1. На странице GitHub Releases скачайте `MCP-Hub-Windows-x64.zip`.
2. Распакуйте папку и запустите `MCP-Hub.exe` — Python устанавливать не нужно.
3. Откроется `http://127.0.0.1:8765/`. При первом входе задайте пароль.
4. Откройте вкладку **Компоненты**. У каждого компонента есть отдельная карточка с версией, путём, зависимостями и своей кнопкой установки. Во время загрузки прогресс виден прямо в карточке, в закреплённом индикаторе и в журнале; для файлов показываются объём и скорость, а для npm/winget — живой анимированный статус и прошедшее время. Для Desktop Commander последовательно установите Node.js, supergateway и **Desktop Commander**.
5. Откройте **MCP Studio**: создайте новый MCP или выберите существующий, настройте его порт, маршрут и авторизацию.
6. В **Tools Explorer** выберите конкретный MCP либо вставьте URL (например `https://mcp.riseshield.ru/roblox`), получите только его список tools и запустите нужный tool с JSON-аргументами.
   На странице каждого сервиса кнопка **Проверить всю цепочку** последовательно
   проверяет конфигурацию, процесс и порт, прямой upstream, Inspector и публичный
   маршрут. Результат и хвост журнала можно скопировать из панели одним JSON.
7. Включите только нужные MCP тумблерами. При внешней публикации откройте HTTPS-порт в **Настройки → Windows Firewall** и подтвердите UAC.
8. В **Настройки → SSL-сертификат домена** нажмите **Выпустить / проверить SSL**.

Закрытие окна `MCP-Hub.exe` останавливает панель, но не обрывает уже запущенные MCP. Полная остановка доступна в панели кнопкой **Остановить всё**.

### Для разработчика из исходников

Установите Python 3.8+, клонируйте репозиторий и запустите `start.bat`. Обязательных pip-пакетов нет.

## Обновление со старой версии

```bash
python run.py --import-env /путь/к/старому/.env
```

Импортируются домен, email, токен, порты и внешний upstream. Флаги сервисов остаются выключенными, чтобы обновление ничего неожиданно не опубликовало.

## Схема трафика

```text
MCP client / Tools Explorer
    │ HTTPS / HTTP/2, Hub token / OAuth / none
    ▼
  Caddy :8443
    │ /mcp* → /_inspect/dc
    ▼
Inspector :8770 ── records JSON-RPC call ──► SQLite/WAL
    │ streaming HTTP, no buffering                  │
    ▼                                               ▼ SSE push
MCP upstream                                  Browser panel :8765
```

Caddy публикует только включённые сервисы. Админ-панель и inspector слушают `127.0.0.1`; снаружи панель доступна только через `/admin/` в Caddy.

## Почему SSE, а не gRPC-web

Для этой задачи сервер почти всегда отправляет браузеру маленькие однонаправленные события: завершился tool call, изменился процесс, пришла строка установки. Браузер не поддерживает raw gRPC, поэтому gRPC-web добавил бы protobuf-кодогенерацию и translating proxy. SSE даёт нужные свойства без зависимостей:

- один долгоживущий поток поверх HTTP/2;
- доставка события сразу после `COMMIT` телеметрии;
- встроенное переподключение браузера;
- восстановление пропущенных событий через `Last-Event-ID`;
- heartbeat через 15 секунд;
- backpressure: медленный клиент отключается, а не расходует память бесконечно.

Управляющие команды идут через один компактный RPC endpoint и поддерживают пакетные запросы. MCP-потоки по-прежнему используют Streamable HTTP/SSE — inspector передаёт чанки немедленно.

## Безопасность

- панель и inspector bind'ятся только к loopback;
- пароль хранится как PBKDF2-SHA256 с 240 000 итераций и случайной солью;
- сессия — HttpOnly, SameSite=Strict, с ограниченным сроком;
- после серии неверных паролей действует временная блокировка;
- публичный MCP-маршрут по умолчанию требует случайный Bearer token; для каждого сервиса отдельно можно включить RFC 7662 OAuth introspection или осознанно отключить auth;
- OAuth Client Secret и upstream token не возвращаются из backend в интерфейс;
- конфиг, токен, пароль, SQLite, логи и скачанные бинарники исключены из Git;
- скачанный Caddy проверяется по официальному `checksums.txt`;
- Caddyfile содержит только включённые MCP.

Не публикуйте порт панели `8765` и inspector `8770` напрямую в интернет. Для внешнего доступа пробра��ывайте только WAN `443 → этот ПК:8443` либо используйте Tailscale/туннель.

При схеме `WAN 443 → LAN 8443` в настройках MCP Hub укажите **Порт HTTPS = 8443**, а **Bind оставьте пустым**. Поле Bind принимает только локальный IP-адрес, а не порт и не запись вида `8443:443`. Это позволяет Tailscale продолжать использовать локальный порт 443.

## SSL-сертификат домена

Отдельный certbot не нужен: сертификат выпускает встроенный Caddy.

1. Укажите публичный домен и необязательный ACME email.
2. A/AAAA-запись домена должна указывать на публичный адрес вашей сети.
3. Для локального порта `8443` настройте `WAN 443 → компьютер:8443` и разрешите `8443` в Windows Firewall; для локального `443` нужен прямой внешний TCP 443.
4. Нажмите **Настройки → SSL-сертификат домена → Выпустить / проверить SSL**.
5. Панель проверит issuer, цепочку доверия, доменное имя и срок действия.

Если сертификат не появился за минуту, Caddy продолжит попытки в фоне. Исправьте DNS/проброс порта и нажмите **Обновить статус**. Продление выполняется автоматически.

## MCP Studio

Откройте **MCP Studio → + Новый**:

- `stdio`: укажите команду, локальный порт и upstream path. В команде можно использовать `{port}`. Хаб запускает и останавливает процесс.
- `remote`: укажите URL уже работающего Streamable HTTP MCP. Хаб только проксирует и наблюдает за ним.
- `authMode`: `token`, `oauth` (RFC 7662 introspection) или `none` для публичного маршрута.
- `upstreamAuthMode`: `none`, `bearer` или `oauth` Client Credentials для удалённого upstream.

Сервис создаётся выключенным. После включения Caddyfile перестраивается, а Caddy получает hot reload без разрыва существующих соединений. Порты проверяются на диапазон и конфликты до сохранения.

### Tools Explorer

1. Выберите настроенный MCP или пункт **Произвольный адрес**.
2. Вставьте полный Streamable HTTP endpoint, например `https://mcp.riseshield.ru/roblox`.
3. Выберите автоматическую авторизацию сервиса, Hub token, Bearer, OAuth Client Credentials или `none`.
4. Нажмите **Получить список tools**. Хаб выполнит `initialize`, сохранит `Mcp-Session-Id` и запросит постраничный `tools/list` только у этого endpoint.
5. Выберите tool, проверьте его input schema, заполните JSON и нажмите **Запустить tool**.

Поддерживаются JSON и SSE-ответы. Таймаут настраивается от 3 до 120 секунд, ответ ограничен 4 МБ.

## ComfyUI

Встроенный сервис **ComfyUI** выключен по умолчанию. Включите его в панели:
Hub запустит loopback-адаптер, а публичный маршрут `/comfyui` будет защищён
общим OAuth Hub (DCR + PKCE). Режим доступа можно изменить в MCP Studio.
Сохраняются маршрут `/stabilitymatrix` и старые имена tools `stabilitymatrix_*`;
новые tools называются `comfyui_*`.

Поддерживаются Config/Prompt, список моделей, Generate, сравнение двух генераций
с общим seed и фоновая загрузка моделей. Результат содержит нативный MCP
`ImageContent`, подписанные ссылки и MCP Apps-карточки. В History ComfyUI
сохраняется редактируемый workflow. Генерация по референсу принимает составленное
клиентом текстовое описание; исходные пиксели референса не передаются в ComfyUI.

Настройки в `config/hub.json` (после изменения перезапустите Hub):

| Ключ | По умолчанию | Назначение |
| --- | --- | --- |
| `comfyuiApiUrl` | `http://127.0.0.1:8188` | Адрес установленного ComfyUI API |
| `comfyuiPath` | пусто | Каталог с `main.py` и `venv`; также поддерживаются `COMFYUI_PATH` и `STABILITY_MATRIX_COMFYUI` |
| `comfyuiAutoStart` | `true` | Запуск локального ComfyUI по требованию |
| `comfyuiListen` | `127.0.0.1` | Bind ComfyUI при автозапуске |
| `stabilityMatrixPort` | `8780` | Loopback-порт адаптера; выберите свободный порт |
| `stabilityMatrixWebUrl` | `http://localhost:8188` | Ссылка Open in ComfyUI, доступная клиенту |
| `behindProxy` | `false` | HTTP между внешним TLS reverse proxy и Caddy |

Для удалённого ComfyUI укажите `comfyuiApiUrl` и отключите автозапуск. Установка
ComfyUI, Python-окружения и моделей выполняется отдельно. Загрузчик моделей
принимает публичные HTTPS URL, проверяет каждый redirect и соединяется с
проверенным IP, сохраняя TLS-проверку имени. Proxy environment variables для
этих загрузок не используются. Файлы публикуются атомарно, существующие модели
не перезаписываются. `STABILITY_MATRIX_MODELS` задаёт общую библиотеку моделей.

Подписанные ссылки на изображения и прогресс загрузки дают доступ без входа:
передавайте их только тем, кому разрешён доступ к результату. Отключение сервиса
убирает публичные маршруты и останавливает адаптер, сохраняя ComfyUI и его задания.
Данные профиля находятся в `data/stabilitymatrix.json`.

При обновлении с отдельного локального `stabilitymatrix_oauth.py` потребуется
заново авторизовать MCP-клиент через общий OAuth Hub; старое хранилище токенов
не импортируется. Профиль и пути ComfyUI сохраняются.

## Выпуск релиза

При push тега `v*` GitHub Actions прогоняет тесты на Windows/Linux и собирает portable `MCP-Hub.exe` через зафиксированную версию PyInstaller. Бинарник и документация автоматически упаковываются в `MCP-Hub-Windows-x64.zip` и прикрепляются к GitHub Release. Бинарники не хранятся в Git, поэтому репозиторий остаётся лёгким.
