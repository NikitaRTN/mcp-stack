# MCP Hub 3.4.1 — самовосстановление npm и MCP

- Установщик показывает реальные строки npm, активный registry и текущий этап вместо
  одного бесконечного сообщения «Скачивается…».
- Добавлена остановка зависшей установки с корректным завершением дерева процессов.
- Desktop Commander прогревается в той же версии `0.2.48`, которая запускается сервисом.
- Если npm-зеркало возвращает `ETARGET`, `E404` или не содержит транзитивную зависимость,
  установка автоматически повторяется через официальный `registry.npmjs.org`.
- В интерфейсе компонентов появился npm-диагност с кнопкой автоматического исправления:
  он убирает конфликтующую переменную окружения, переключает registry и перезапускает
  включённые npx-сервисы.
- Диагностика MCP теперь отображается понятным чек-листом и предлагает безопасное
  действие для первого сломанного звена: исправить npm, перезапустить MCP или применить Caddy.
- Определение npm-пакетов использует фактический путь кеша из `npm config get cache`.

# MCP Hub 3.3.1

## Исправления и SSL

- Исправлена бесконечная ошибка `client.log`: metadata больше не дублирует аргумент `event`, а диагностический RPC не отправляет собственную ошибку обратно в очередь.
- В **Настройки → SSL-сертификат домена** добавлены DNS, статус Caddy, issuer, срок действия и кнопка **Выпустить / проверить SSL**.
- Кнопка запускает/перезагружает Caddy, инициирует ACME Let's Encrypt и проверяет цепочку доверия, домен, SAN и срок действия.
- Для локального `8443` показывается обязательный проброс `WAN 443 → LAN 8443`; для `443` работает прямой TLS-ALPN.
- Caddy автоматически продлевает сертификат после выпуска.
- Пройдено 28 backend-тестов, включая client.log, Caddyfile 443/8443 и цикл выпуска сертификата.

## MCP Hub 3.3.0

## MCP Studio — рабочее пространство разработчика

- Добавлена отдельная вкладка **MCP Studio** для создания, редактирования, включения и удаления MCP без ручной правки `hub.json`.
- Поддерживаются локальные `stdio`-команды через supergateway и уже работающие Streamable HTTP MCP.
- Для локального MCP можно менять порт, команду и upstream path; конфликты с HTTPS, панелью, inspector и другими MCP блокируются до сохранения.
- Tools Explorer подключается к одному выбранному MCP или произвольному URL, включая `https://mcp.riseshield.ru/roblox`.
- Реализованы MCP `initialize`, `notifications/initialized`, постраничный `tools/list` и `tools/call`.
- Показаны описание и input schema каждого tool, JSON-редактор аргументов, сырой ответ и время выполнения.
- Клиент понимает JSON и SSE, поддерживает `Mcp-Session-Id`, ограничивает размер ответа и имеет настраиваемый таймаут.

## Авторизация каждого MCP

- Публичный маршрут каждого MCP отдельно переключается между глобальным токеном Hub, OAuth 2.0 и режимом без авторизации.
- OAuth-защита публичного маршрута использует RFC 7662 token introspection и может требовать конкретные scopes.
- Удалённый upstream отдельно поддерживает `none`, Bearer token и OAuth Client Credentials.
- Tools Explorer умеет автоматически брать авторизацию выбранного MCP либо использовать свой Bearer/OAuth Client Credentials.
- Входящий `Authorization` больше не передаётся в upstream неявно.
- Client Secret и upstream token не возвращаются в состояние интерфейса; панель показывает только признак сохранённого секрета.

## Порты и Windows Firewall

- В настройках доступны HTTPS-порт, порт панели и порт inspector; изменения панели и inspector помечаются как требующие перезапуска.
- В Windows публичный HTTPS-порт можно добавить в Firewall после явного подтверждения пользователя.
- Системные права запрашиваются стандартным UAC; поддержаны private, domain, private+domain и все профили сети.
- Правило можно проверить и удалить из интерфейса. Внутренние MCP-порты автоматически наружу не открываются.

## Проверки

- Пройдено 23 Python-теста, compileall, проверка синтаксиса всех ES-модулей и браузерный QA desktop/mobile без горизонтального overflow и console errors.
